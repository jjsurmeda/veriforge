| ID | Requirement |
| --- | --- |
| TR-4 | Auto retrieves once, and if the evidence is insufficient it rewrites the question and retries **once**. It then abstains when **either** check fails: *sufficiency* (do the passages together answer the question?) or *answerability* (does any passage actually contain the answer, or for a summary question, do the passages cover the subject?). ## 4.7 OKF: Open Knowledge Format *(new)*

An OKF bundle is a folder of markdown files, one concept per file:
- YAML frontmatter: a required `type`, plus `title`, `description`,
  `resource` and `tags`
- markdown links between files, which form a graph
- v0.2 trust signals: `sources`, `generated` and `verified` (each
  `{by, at}`, with `by` as `human:<id>` or `agent/<version>`), `status`
  (draft/stable/deprecated) and `stale_after`

Veriforge reads and writes this format; it doesn't replace search with it.

| ID | Requirement |
| --- | --- |
| OK-1 | A user uploads an OKF bundle as chat sources, and an admin uploads one to the Shared library. Each concept becomes a source document that is searched together with all other documents (one hybrid search, no separate "OKF mode"). |
| OK-2 | Frontmatter becomes searchable metadata (title, type, tags, status, verification, staleness) and **never appears in the passage text** shown, cited or sent to the generator. A concept without a `type`, or with invalid YAML, is rejected with a reason; the rest of the bundle still ingests. |
| OK-3 | Links between concepts are kept. In Auto, the passages a retrieved concept links to directly may be added to the evidence: one hop, bounded by an admin limit, and only within what this chat is allowed to search. In Deep, following a link is one of the hop choices the planner can make. |
| OK-4 | **A link never widens access.** A link to a concept outside the chat's sources and the Shared library is not followed, and the skip is shown in the trace. Linked passages pass the same injection checks as retrieved ones. |
| OK-5 | Trust signals shape results: `deprecated` concepts are excluded by default; concepts past `stale_after` are shown with a "stale" badge; an admin can prefer human-verified concepts in ranking. The Sources panel and citation hover show the status and who verified the concept. |
| OK-6 | When concepts conflict (for example, a `stable` and a `deprecated` version), the answer follows TR-5's conflict disclosure, and status breaks the tie by default. |
| OK-7 | **Export:** any answer that passed review can be downloaded as an OKF concept. `sources` comes from its citations, `generated` records the model and run, `verified` records the Jev claim check (`agent/jev-…`) and, after a thumbs-up, the user (`human:<id>`). `status` is `draft` until a human verifies it, then `stable`. |
| OK-8 | Exported concepts re-import cleanly: an exported answer uploaded as a bundle is valid OKF and keeps its trust signals. |
| OK-9 | Multilingual concepts follow SR-7. |

## 5. Non-functional requirements: changed and new rows

v1 is accepted when the targets below hold **on three corpora** (books,
product manuals, an OKF bundle) **plus a counterfactual corpus** of documents
whose facts deliberately differ from the real world, so answers must come from
the documents, not from model memory. Latency is measured from AWS Singapore.
Until slice 9 it's measured locally, as an upper bound.

| Area | Target |
| --- | --- |
| Faithfulness | ≥ 0.90 mean per corpus; minimum claim support ≥ 0.6 on ≥ 95% of answers |
| Abstention | ≥ 90% correct abstentions; **0 confident wrong answers** on should-abstain questions over 3 consecutive runs; ≤ 5% false abstentions, **including broad/summary questions** |
| Grounding | On the counterfactual corpus, ≥ 95% of answers follow the document, not the real-world fact |
| Context recall | ≥ 0.85 per corpus |
| Latency, first progress | First trace step ≤ 1 s p95 |
| Latency, Auto | First answer token ≤ 5 s p50, ≤ 8 s p95 |
| Latency, Fast | First token ≤ 2 s p50 |
| Latency, Deep | Complete ≤ 30 s p50, including OKF link traversal |
| OKF ingestion | A 500-concept bundle is searchable in ≤ 3 min; OKF link expansion adds ≤ 500 ms p50 to Auto |
| Security | Server-side ownership filter on every retrieval **and every followed link** (OK-4) |

Other v2 rows (decision layer, ingestion, availability, cost, accessibility)
are unchanged.

## Decisions this draft makes for you (change any before approval)

1. Latency: progress ≤ 1 s; Auto first token ≤ 5 s p50 / ≤ 8 s p95.
2. Abstention: ≥ 90%, zero confident wrong answers, ≤ 5% false abstention.
3. OKF: a link never crosses outside the chat's scope (OK-4).
4. OKF: `deprecated` is excluded by default and `stale` is shown, not hidden
   (OK-5).
5. OKF export in v1 (OK-7/8), not only import.
6. Bundle limits: 20 MB / 2,000 concepts; ingestion ≤ 3 min for 500.
7. A counterfactual corpus is part of v1 acceptance.
