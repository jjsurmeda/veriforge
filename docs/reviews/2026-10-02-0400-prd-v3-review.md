## 1. Verdict

**Approve with changes. Two items need rework before approval.** The
direction holds up: TR-4 is realigned to answer-first, the Jev reranker moves
to v1, and OKF is modelled as documents, not a new `source_type`. Most OKF
rows can be built on the current scope and ingestion design.

The two items that need rework:

- **CH-5's token target.** Neither the current pipeline nor the planned
  speedups can meet 5 s p50 / 8 s p95 for every Auto reply, and the draft
  doesn't say whether declines and held answers are in scope.
- **The quality targets.** Several can't be measured with the eval harness
  as it is. "0 confident wrong answers" is undefined and fails today.

The rest needs wording changes, not redesign.

## 4. Coverage gaps (architecture → PRD)

1. **Auto has no multi-hop.** CH-2 and TRD §7 still describe one (F12).
2. **Fast mode has no sanitizer, no ingress guardrails and no abstention.**
   `fast.py` imports no DecisionEngine. The PRD never says Fast skips
   TR-4 or the injection checks. That's acceptable for an API/eval-only mode
   (CH-1), but it should be stated.
3. **The relevance gate depends on the reranker** (`auto.py:726`), and the
   reranker is now an admin setting (F4, F14).
4. **Held answers (TR-6) deliver the first token after review.** That's
   built (`review.py:106–120`), and CH-5 doesn't account for it (F1).
5. **Conflict side assignment is a midpoint split** (`auto.py:849–856`), so
   TR-5's "cites both sides" isn't met, and OK-6 builds on it (F7).
6. **KI-24: the eval corpus is in the Shared library.** Every user searches
   it, and the `not_in_sources` passes partly depend on it. The v3 acceptance
   rule ("three corpora") inherits this unless P5 lands first. OK-1's admin
   Shared upload repeats the pattern for OKF.
7. **Language detection is stop-word based and misreads short French as
   Spanish.** It affects TR-4, SR-7 and the acceptance scorer (F4).
8. **The eval gate has never actually run in CI**, and it is expected to fail
   on the overhead factor (D4 lines 105–113, 452–461). v3's "eval gate before
   merge" for prompt changes (TR-8, OK-6) depends on it.
9. **Reset email is dev-log only** (AC-1, F13).
10. **Step events in Auto aren't published live** (F2). TX-1 ("streams …
    each step") is weaker in Auto than the PRD implies.

## 5. What holds up

- **OKF as `documents` with `format` / `okf_meta`, not a new
  `source_type`.** Verified sound. `build_scope`'s document branch
  (`filters.py:62–67`) and `resolve_scope` (`scope.py:22–37`) apply
  unchanged, and SR-6's OKF filters fit as extra `doc_clauses`. A new
  `source_type` would have needed a third OR-branch and its own ownership
  tests.
- **OK-4's "a link never widens access"** matches CLAUDE.md and the existing
  single-predicate design. "Linked passages pass the same injection checks"
  is the right rule (plan K4).
- **TR-4's retry and no-citation clauses match the code:**
  `MAX_SUFFICIENT_RETRIES = 1`, clamped at `auto.py:672`; no contexts or
  citations on decline at `auto.py:815–817`, KI-25.
- **Moving the Jev reranker to v1 is factual:** `1ba8f3f`, KI-28, and the
  relevance gate depends on it.
- **The revision-table claims check out:** 13/14 should-abstain on
  acceptance and faithfulness 0.95–0.98 on fast20 (D4).
- **TX-6 and AD-7 "not built" is correct:** there are no routes in the API
  or the web app.
- **Admitting that latency can't hit 3 s and that an ADR is needed** is the
  honest call. The base plan's P3 expected exactly this.
- **Sequencing OKF after P2 and before P3 / P7** (the OKF plan) is right, and
  the draft's follow-up list points at it.
