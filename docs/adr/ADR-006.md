# ADR-006: Auto's evidence check: a floor before generation, a usefulness check after

**Status:** Accepted, 2026-10-17 (replaces the 2026-10-13 decision).
**Full context:** PRD TR-4; TRD §7, §8, §10.

## Context

Auto used to decline on three vetoes in series (sufficiency, a relevance floor,
an entity check). Each produced its own false declines, and none tried to fix
weak evidence first. The 2026-10-13 version of this ADR replaced them with one
pre-generation gate: the reranker's answer-containment grade, averaged over the
best three passages.

The measurements disproved that gate (`docs/history/reports/2026-10-17-0140-r2a-gate-findings.md`):

- **No cutoff on the grade separates.** Should-decline items reach 0.56
  (`outside-holmes-boston`); answerable items fall to 0.47 (fast20
  `injection-01`, `keyword-04`). This held across three fast20 runs, and the
  books calibration agrees. A lookup's answer sits in one passage, and the
  mean of three dilutes it. A gist question has no single passage that
  "fully answers".
- **`sufficient` doesn't separate either.** Replayed as the only check, it
  turned 12 of 21 should-decline items into confident wrong answers.
- **The claim reviewer can't arbitrate.** In 81 recorded runs and the IsUse
  probe, it passed 3 of 5 confident-wrong answers at min_support 0.81–0.94.
  Their claims were true sentences that didn't answer the question. It also
  scored correct gist answers 0.0. It measures support (Self-RAG's IsSup),
  not whether the question was answered.
- **An answer-usefulness question does separate.** Self-RAG's IsUse, asked
  of the generated answer and its sources, ran on 19 in-band items with the
  gate forced open. Should-decline answers scored 0.09–0.37; answerables
  scored 0.56–0.93, with one miss (`outside-whitman`, 0.11). That is 0
  confident wrong and 1 false abstention on that sample, and `broad-alice` and
  `broad-bovary` were recovered.

## Decision

Self-RAG's split, using signals Veriforge already has: relevance before
generation, usefulness after.

1. **Floor before generation (IsRel).** The rubric grade (mean of the top 3)
   below a calibrated floor means the evidence is clearly absent. That
   triggers one corrective retrieval (a rewritten or decomposed query, with
   summaries for gist questions), a re-grade, and then abstain. The floor sits
   below the lowest answerable reading, so it only removes clear misses and
   saves their generation cost.
2. **The entity guard stays,** unchanged: passages about a different entity
   than the one asked about are not evidence.
3. **Usefulness after generation (IsUse).** Every generated Auto answer gets
   one `Noul` through `DecisionEngine`: "Does the answer directly answer the
   question that was asked, using what the sources state?" Below its
   calibrated threshold, the run abstains instead of delivering, with the
   normal found/missing decline (TR-4).
4. **Risk-based delivery (TRD §10, `plan_delivery`).** Answers whose grade is
   clearly present (at or above a calibrated stream line, set above every
   should-decline reading seen; 0.56 so far) stream, and IsUse still runs on
   them: a failure retracts the answer and declines. In-band answers and
   high-risk intents are held under a visible "verifying" step until IsUse
   passes. This is the synchronous/asynchronous split proven guardrail systems
   offer (AWS Bedrock Guardrails, NeMo streaming output rails): hold where a
   wrong answer is likely, stream where it isn't. Phase 3 measures the held
   path's first token; if it misses, chunked release comes before full
   retraction.
5. **The reviewer stays a faithfulness signal,** not a gate. It still scores
   claims, revises once, and feeds the trace and metrics. It never decides
   answer versus abstain.
6. `sufficient` is removed. The rubric grade is no longer the delivery gate,
   only the floor.

## Consequences

- One floor and one post-generation check replace a gate that couldn't be
  calibrated. The deciding question is asked of the answer itself, which is
  where the confident-wrong failures showed up.
- Every answered run costs one more Jev call (about 0.5–1 s). In-band runs
  lose streaming, about 2–4 s more to the first token. Clearly-present runs
  keep it, with a rare retraction when IsUse fails after streaming.
- The calibration so far is in-sample (n = 19). The IsUse threshold and the
  floor are confirmed on the held-out set and validated on fast20 before
  merge, and a held-out failure reopens this ADR.
- Any change to these checks is replayed against recorded runs before it is
  briefed. Eval exports now keep each item's decision trail, so that replay
  costs $0.

## Held-out result (2026-10-19, R2a close)

The held-out set (31 items over five unseen books) scored 29/31: 0 of 21 answerable
items declined, 9 of 10 should-declines declined, **1 confident wrong**
(`ho-near-vlad`, a false-premise question; KI-78) against a bar of 0, and one allowed
content miss (a label that was too narrow, left unchanged because the set is frozen).
The books acceptance run missed its false-abstention bar by one (2 of 33:
`outside-whitman`, a label miss (not chunking; removed from the set 2026-10-22, KI-80), and `plot-speckled-band`; KI-79, KI-80).
Swapping only the generator showed both generation failures are the generator
(`gpt-4o-mini`), not retrieval or the checks: `gpt-4o` answered speckled-band 2/2 and
declined the false premise. The decisions stand (floor 0.455, IsUse 0.47, stream line
0.60); the floor and IsUse run on Jev, not the generator, so a generator change does
not move them. The owner accepted these misses for the R2a merge and moved the
generator question to R3, re-measured on the production model.
