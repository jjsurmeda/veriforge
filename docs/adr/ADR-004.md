# ADR-004: OKF concepts are documents with a link graph

**Status:** Accepted, 2026-10-02.
**Full context:** PRD §4.7 OK-0 to OK-10 (v3); TRD §9.5, §8, §12; reviews
`docs/reviews/2026-10-02-0400-prd-v3-review.md` and `…-0420-…`.

## Context

Google's Open Knowledge Format (v0.2) is a bundle of markdown files, one
concept per file. Each has YAML frontmatter (required `type`, plus `title`,
`description`, `resource` and `tags`), markdown links between files, and
trust signals (`sources`, `generated`, `verified`, `status`,
`stale_after`). It's only a format: there's no runtime, index or model.
Veriforge should consume it (search it, follow its links) and produce it
(export verified answers).

Two storage options were considered:
- a new `source_type = 'okf'`, which would need a third OR-branch in
  `build_scope` and its own ownership tests
- documents with OKF metadata

## Decision

1. **A concept is a `documents` row with `format = 'okf'` and `okf_meta`
   (JSONB).** `source_type` stays `document`, so `build_scope`, the
   ownership filter, hybrid retrieval and citations apply unchanged. SR-6's
   OKF filters are extra document clauses on `okf_meta`, and filters only
   narrow.
2. **Identity is (collection, bundle, bundle-relative path)**, not
   `sha256`. Re-upload syncs: changed concepts are replaced, missing ones
   retired, and both become non-searchable versions that keep their chunks,
   so historical citations resolve.
3. **Bundle handling at the trust boundary:**
   - compressed ≤ 20 MB, uncompressed ≤ 100 MB, ≤ 2,000 concepts
   - reject absolute and `..` paths
   - skip reserved files
   - `resource` is **never fetched**
4. **Frontmatter is stripped before chunking.** Server-derived `status`,
   `verified` and `stale` reach the generator only as attributes on the
   `<source>` wrapper.
5. **Links are edges** (`okf_links`). Within a bundle they resolve by
   relative path; across bundles only by `resource` id. They're followed
   **only inside the chat's scope**, and a skipped link is reported
   identically whatever the reason (no existence oracle). In Auto, linked
   passages are added **after** both evidence gates, are sanitized and
   timed, and are bounded to one hop and an admin limit. In Deep, following
   a link is a `follow_link` option on the controller's DecisionEngine
   `Choice`, never a planner LLM decision.
6. **Trust:**
   - `deprecated` is excluded by a server-side default
   - stale concepts are flagged
   - optional trust ordering is applied after the top-k cut and the gates
   - the gates always read raw Jev scores
   - thresholds may get per-format overrides, checked on OKF items (K6)
7. **One ingestion job per bundle,** with embeddings batched across concepts
   and one starter-question job per bundle.
8. **Export:** a reviewed answer becomes a concept.
   - `sources` = citations; `generated` = model and run
   - `verified` = the actual verdict engine, plus an explicit human
     "Verify" action with a pseudonymous id
   - `status` is draft until human-verified, then stable
   - exports re-import cleanly

## Consequences

- New migration: `documents.format`, `documents.okf_meta`, the OKF
  uniqueness rule, version retention, `okf_links`.
- New optional `RetrievedChunk` fields and a TS regen; no new SSE event
  types.
- OKF work is gated like any quality change. Isolation run first (OKF
  ingested but out of scope must match the baseline), items before code,
  a flag `okf.enabled` defaulting off until the gates pass, ownership
  tests on every link path.
- Depends on KI-34 for status-based conflict tie-breaking (OK-6).
