# ADR-002: Chat-scoped sources and a Library, no user-facing collections

**Status:** Accepted, 2026-09-26.
**Full context:** PRD SR-1, SR-5, SR-6, CH-9; TRD §9.1–9.3, §12, §13
(source of truth if this file and the TRD ever disagree, the TRD wins).

## Decision

Users stop managing collections. Sources live in two places:

- **Chat sources.** Files uploaded into a chat belong to that chat only
  and are deleted with it.
- **Library.** A user's own documents plus admin-published Shared
  documents. The Library is added to a chat's scope when that chat's
  `include_library` switch is on (default).

The `collections` table stays as a hidden container, so the ownership
filter, retrieval SQL, ingestion and dedupe are unchanged:

| Container | `kind` | `chat_id` | `visibility` | Owner |
| --- | --- | --- | --- | --- |
| A chat's sources | `chat` | the chat (unique, cascade) | `private` | chat's user |
| A user's Library | `library` | null | `private` | user |
| Shared (admin) | `library` | null | `shared` | admin |

A run's scope is resolved on the server from the chat alone: its `chat`
collection, plus, if `include_library`, every `library` collection the
user owns and every `shared` collection. The run request no longer carries
`collection_ids`; client filters (document, tag, date, MIME, page, source
type) can still only narrow.

## Context

Picking collections per chat was friction: users had to create a
collection, upload into it, then attach it to each chat. Most chats are
about a handful of files the user drops in at the start. A few documents
(policies, product specs) are wanted everywhere.

Dropping collections from the schema was considered: put `chat_id` on
`documents` and rewrite `build_scope`. Rejected because it churns the
retrieval SQL and every ownership test for no user-visible gain.

## Consequences

- Scope resolution is one server-side function, covered by ownership tests
  (another user's chat or private Library is never in scope; Shared only
  when `include_library`).
- The same file uploaded into two chats is embedded twice (dedupe is per
  collection). Acceptable at demo scale; revisit if embedding cost matters.
- Existing collections migrate to `kind = library`, so a user may own
  several Library collections. The UI shows one flat Library list; new
  Library uploads go to the user's oldest Library collection.
- Evals keep loading the seed corpus as a Shared collection, so the eval
  gate is unaffected as long as eval runs resolve scope with the Library
  included.
