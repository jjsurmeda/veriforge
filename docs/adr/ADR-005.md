# ADR-005: Decision providers and rerankers are pluggable per run

**Status:** Accepted, 2026-10-13.
**Full context:** PRD goal 7, AD-10 to AD-12; TRD §8, §9.6.

## Context

Veriforge is a showcase of the decision layer. Every routing, scoring and
verification decision already goes through `DecisionEngine`, but Jev was the
only primary engine and the reranker was chosen globally. Showing how
decision models and rerankers differ needs them interchangeable on the same
question.

## Decision

- `DecisionProvider` interface (`decide(state, questions) -> answers` over
  `Noul`, `Choice`, `Score`). Implementations: Jev (default primary), an LLM
  judge (default fallback), and other decision models from OpenRouter's
  decision list. `DecisionEngine` keeps the fallback, breaker and shadow
  sampling, over whichever providers are selected.
- `Reranker` interface. Implementations: Cohere, NVIDIA, Jev with the
  answer-containment rubric, an LLM judge, and fused order.
- Selection per run: admin defaults; eval runs and the comparison view
  override for one run. Thresholds are stored per provider.
- One benchmark command writes comparison tables to `docs/benchmarks/`.

## Consequences

- Every provider needs contract tests and its own calibrated thresholds
  before it can be a default.
- Decision events record the provider, so traces and the comparison view
  can attribute every verdict, latency and cost.
- OKF (v1.1) adds a `follow_link` option to the agent `Choice`; it works
  with any provider.
