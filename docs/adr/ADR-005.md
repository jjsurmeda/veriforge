# ADR-005: Decision providers and rerankers are pluggable per run

**Status:** Accepted, 2026-10-13.
**Full context:** PRD goal 7, AD-10 to AD-12; TRD §8, §9.6.

## Context

Veriforge is a showcase of the decision layer. Every routing, scoring and
verification decision already goes through `DecisionEngine`, but Jev was the
only primary engine and the reranker was chosen globally. Showing how
decision models and rerankers differ needs them interchangeable on the same
question.

## Decision

- `DecisionProvider` interface (`decide(state, questions) -> answers` over
  `Noul`, `Choice`, `Score`). Implementations: Jev (default primary), an LLM
  judge (default fallback), and other decision models from OpenRouter's
  decision list. `DecisionEngine` keeps the fallback, breaker and shadow
  sampling, over whichever providers are selected.
- `Reranker` interface. Implementations: Cohere, NVIDIA, Jev with the
  answer-containment rubric, an LLM judge, and fused order.
- Selection per run: admin defaults; eval runs and the comparison view
  override for one run. Thresholds are stored per provider.
- One benchmark command writes comparison tables to `docs/benchmarks/`.

## Consequences

- Every provider needs contract tests and its own calibrated thresholds
  before it can be a default.
- Decision events record the provider, so traces and the comparison view
  can attribute every verdict, latency and cost.
- OKF (v1.1) adds a `follow_link` option to the agent `Choice`; it works
  with any provider.

## Implemented 2026-10-19 (R2c): rerankers

**Pluggable now:** the reranker. `retrieval/rerank.py` holds one registry
(`RERANKERS`: `jev`, `cohere`, `nvidia`, `fused`) with label, kind
(`decision-model` or `traditional`), key presence, calibration and a rough cost
per 1,000 queries; `GET /rerankers` lists it. `POST /chats/{id}/runs` takes an
optional `reranker`; absent, the admin default (`retrieval.reranker`) applies.
Auto, Deep and Fast read the choice through the same runtime seam, and
`runs.metrics.reranker` records it. An unknown or keyless id fails with
`reranker_unavailable`, an uncalibrated one with `reranker_uncalibrated`; neither
ever falls through to Jev. An admin-forced uncalibrated default fails the first
run for the same reason.

**Thresholds per reranker, fail closed:** `evidence_floor` and `stream_line` are
looked up by the reranker that produced the grade (`reranker_threshold`). Jev
keeps 0.455 and 0.60 (and its fallback cell). Cohere, NVIDIA and fused order have
no values until `scripts/calibrate_gate.py --reranker <id>` has run and a human
has reviewed and pasted them, so today only Jev is selectable. The gate's trace
row carries the real reranker id.

**Not pluggable yet:** decision models (Laya, Microsoft-Decision-1). The
decision-engine thresholds (`entity_match`, guards, IsUse) are still keyed
`"jev"` / `"fallback"` and listed in KI-85. The LLM-judge reranker, the UI
picker and the side-by-side trace view are later work.

`scripts/compare_rerankers.py` is the comparison harness; its output is
`docs/benchmarks/rerankers.md`.
